# Scoring map — every rubric line, where it is met, and the number

One row per rubric item. **Where** is the code that implements it, **Evidence**
is the artefact a grader can look at, and **The number** is the measured answer
where the item has one. Every figure named here is committed; every number is
regenerated by `amazingscanner refresh` from `outputs/report/*.json` and
guarded in CI, so nothing here can drift from its measurement without the
`documentation integrity` job failing.

## B. Task 1 — the enhancement network — 225

| # | Item | Where | Evidence | The number |
|---|---|---|---|---|
| **B1** | Architecture, designed from scratch | `models/enhance_unet.py::DocEnhanceNet` | `architecture.png`, notebook §3 (live layer table) | **6.0 M parameters** from primitive `torch.nn` layers. **No pre-built U-Net, no torchvision backbone, no pre-trained weights, no dropout** in this version. Encoder–decoder with skip connections (text strokes are 1–2 px and do not survive a 16× bottleneck), dilated context 1/2/4/8, squeeze-excitation, a classical background prior as a fourth input channel, and a zero-initialised residual head so the first forward pass returns the input unchanged |
| **B2** | Training, curves, loss choice | `train.py` → `engine/train_enhance.py` | `training_curves.png`; notebook replots them **live** from `runs/enhance_main/history.json` | Train **and** validation loss per epoch. MSE is known to blur, and blur is the enemy of readable text — so the loss is **L1 + MS-SSIM + Sobel-gradient**, and the choice is *measured*, not asserted: the §3.2 ablation trains MSE, L1 and the combination at a **matched budget** (`loss_ablation_psnr.png`). Trained on 192² crops because resizing a page to 192 turns body text to mush |
| **B3** | Inference pipeline for a rectified page | `pipeline/enhance_pipeline.py` | `amazingscanner enhance page.jpg`; app **Enhance Only** tab ([screenshot with results](assets/app_enhance_result.png)) | Preprocess → predict → post-process to the original size and 8-bit, plus four export styles. Fully convolutional, so inference runs on the whole page at native scale |

## D. Task 2 — corner detection — 150

| # | Item | Where | Evidence | The number |
|---|---|---|---|---|
| **D1** | Approach A — direct coordinate regression | `models/corner_net.py::CornerRegressionNet` | REPORT §2, `approach_a_vs_b.png` | Encoder → FC 256 → 128 → 8 normalised coordinates, Wing loss. **Real photographs: 72.28 px mean, 57.50 px median, 0.747 quad IoU** (quoted at the same shipped setting as Approach B, so the two are comparable) |
| **D2** | Approach B — heatmap regression | `models/corner_net.py::CornerHeatmapNet` | `heatmaps_demo.gif`, app **Corner Lab** ([with results](assets/app_corner_lab_result.png)) | Four Gaussian heatmaps at ¼ resolution + a page-interior mask head, windowed sub-pixel **soft-argmax**, mask-guided quad decoding. | **D3** | Compare the two, with numbers and failure cases | `eval/evaluate.py::evaluate_corners` | `corner_ab_demo.gif`, `real_failures.jpg`, `success_rates.png` | **Prediction written down before the experiment** (heatmaps should win: dense loss, local mapping) and confirmed — B beats A on every set. On real photographs, at the identical setting, **34.06 px vs 72.28 px** mean and **20.91 px vs 57.50 px** median, IoU **0.868 vs 0.747** — B more than halves the error. Both measured on synthetic test, course-only, pseudo-real OOD, MIDV-500 and the 24 own photographs, at four (refine, TTA) settings each |
| **D4** | Inference pipeline for a raw photo | `pipeline/corner_pipeline.py` | `amazingscanner corners photo.jpg`; `qualitative_corners.jpg` | Preprocess → predict → map back to original resolution → draw. Plus a **sanity gate**: a non-convex quad, one covering under 2% of the frame, or a corner more than a quarter-frame outside the image is never returned — it falls back to a classical finder, then to the full frame. On the 120-photo unseen pack the fallbacks **never fired** |

## Two reported numbers

| | Ours | How to read it |
|---|---|---|
| **Test PSNR** | **21.42 dB** (course scans alone: **23.78 dB**) | PSNR is only meaningful against the baseline it improves on, because it is set by *how hard your own degradations are*. Ours start from an **11.70 dB** input — a 34-operator chain including 3× downscale, JPEG down to quality 28, glare, curl and motion blur — so the network adds **+9.72 dB**. A gentler generator yields a higher absolute PSNR from a weaker model; the gain over baseline is the comparable quantity, and the OCR table is the one that tracks the actual goal |
| **Corner error** | **20.55 px** mean, **14.38 px** median (**1.47%** of the image diagonal) | The mean is carried by two photographs — `img9` (88.2 px) and `img4` (65.7 px), both a page lying on other pages. Drop those two known failures and the remaining 22 average ≈15.5 px. Mean quad IoU is **0.90**; on 120 unseen photographs the median is **0.60% of the diagonal** with **120/120 detected by the network itself** |

## What a grader can run in one minute

```bash
pip install -e ".[all]"
amazingscanner scan data/real/own/photos/img1_*.jpg -o /tmp/demo   # H1
amazingscanner app                                                 # G — :7860

# a test set the models have provably never seen, minted on the spot
python scripts/make_test_pack.py --out /tmp/fresh --n 12 --seed 7300
python scripts/score_test_pack.py --pack /tmp/fresh                # A5/C4/D4
```
